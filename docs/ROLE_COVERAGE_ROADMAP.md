# 岗位职责覆盖与证据路线图

## 判断原则

项目是否适合一个岗位，按该岗位常见完整职责判断，而不是按仓库关键词判断。
证据分为五级：

| 等级 | 含义 | 可用于简历结论 |
|---|---|---|
| `missing` | 尚未实现 | 否 |
| `interface` | 只有数据结构或适配器 | 否 |
| `fixture` | 固定样例或故障注入可运行 | 否 |
| `offline_real` | 真实模型/数据/外部系统离线运行，有版本和报告 | 是，须注明离线 |
| `production` | 真实流量、监控、负责人和事故闭环 | 是 |

任何核心职责低于 `offline_real`，岗位结论为 `not_ready`。其他强项不能平均掉核心缺口。

运行当前审计：

```bash
python examples/audit_portfolio_readiness.py \
  examples/fixtures/portfolio_evidence_current.json \
  --out reports/portfolio_readiness.json
```

## 简历投递前硬门槛

### Agent 应用研发

- 接入至少一个真实外部系统，不以 Mock MCP 作为完成证据；
- 50 条以上可追溯业务任务，独立 held-out，报告任务成功率和人工接管率；
- 部署服务经过并发、超时、依赖故障和恢复验证；
- 完成一次真实 Bad Case 修复前后对比；
- 保存 Dataset、Agent、Prompt、工具和代码版本。

### 大模型应用研发

- 同一任务至少比较两个真实模型或两个版本；
- 报告质量、P95 延迟、Token/金额成本和业务 KPI；
- 完成 RAG/Context 的消融实验，而不是只证明能检索；
- 至少完成一次 Shadow 或受控 A/B；无法获得生产流量时，岗位只能标为条件匹配；
- 报告样本量、波动和失败切片。

### Agent 评测

- 覆盖文本/工具 Agent 的真实模型输出与过程证据（步骤分、失败归因、Judge 校准、发布判断）；
- 图像/视频生成横向对比**已删除**，不得再作证据或扩投门槛；

- 自动指标必须保存模型权重、版本、预处理和运行配置（含历史生成跑次）；
- 过程评测人机校准：一致性、仲裁与 held-out Judge 校准；
- 发布结论必须报告置信区间/切片与成本/延迟（若适用）；
- 安全同时报告攻击成功率与良性误拒率。

### AI 应用测试/质量工程

- 确定性与非确定性测试均有真实服务运行证据；
- 负载、超时、限流、外部依赖故障、重试和恢复均有报告；
- 发布门禁在 CI 或发布流程中真实阻断至少一次；
- 至少一个真实缺陷或事故完成根因、回归用例、修复和复测闭环；
- 报告误报、漏报、恢复时间和错误预算，而不只报告测试通过率。

## 执行优先级

1. **P0（主线）：过程评测发布审计** — 轨迹/Judge/门禁证据 manifest + 单一 `release-audit`；打通步骤评测 → 失败归因 → 跨 Agent 发布判断。
2. **P1：取得线上合作入口**，再完成真实可观测、Shadow/A/B 和发布/回滚记录。
3. **P1：记录首个真实生产事故回流**，补齐 Incident 到回归用例的证据链。
4. **已删除：** 图像/视频多模型生成横向对比、CLIP/盲评选型门禁、「多模态生成榜」、图像 v2 `offline_real` 验收口径。

模块初始化不改变岗位结论。只有证据清单升级到 `offline_real` 或 `production`，并通过
`audit_portfolio_readiness.py`，才可以把对应职责写入投递简历。

所有初始化模块的机器可读字段与完成证据定义在
[`examples/fixtures/role_module_contracts.json`](../examples/fixtures/role_module_contracts.json)。
该文件只用于约束后续实现，状态为 `initialized` 不代表模块已经有真实业务证据。
